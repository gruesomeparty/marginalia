# The landing page

One static page, no build step, no external requests — the same rules the
product's own page follows.

`demo.html` is **not** committed. It is a real `marginalia export` of
`demo/handover.md`, generated by `.github/workflows/pages.yml` at deploy time
from the binary in that commit, so the demo in the hero can never drift from
the product it demonstrates.

To preview locally:

```bash
go build -o /tmp/marginalia .
work=$(mktemp -d)
cp site/demo/handover.md site/demo/review.yaml "$work/"
cp site/demo/feedback.jsonl "$work/handover.md.feedback.jsonl"
/tmp/marginalia export "$work/handover.md" --config "$work/review.yaml" \
  --diagrams=off -o site/demo.html
python3 -m http.server -d site 8080
```

`demo/feedback.jsonl` is the seeded review: a sentence-level question, the
agent's threaded answer, a blocker on a diagram edge, and one approval. It is
committed so the demo always shows a review in progress rather than an empty
page.

Diagrams are exported with `--diagrams=off` on purpose: drawing them needs
mermaid-cli, and `export` fails rather than shipping a broken picture. The
anchored source is still clickable, which is the part the demo is showing.
